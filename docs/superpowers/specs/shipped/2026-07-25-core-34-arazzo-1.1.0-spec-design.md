# Arazzo 1.1.0 Spec Support — Design

Stub: [`docs/superpowers/roadmap/backend/phase-0-foundation/core-34-arazzo-1.1.0-spec.md`](../roadmap/backend/phase-0-foundation/core-34-arazzo-1.1.0-spec.md)
Category: **core** · Phase: **0-foundation** · Tier: **OSS**
Depends on: parser + validator + expression resolver (shipped)
Blocks: `ai-10-agent-routing`, `exec-07-saga-compensation`, `tenant-09-context-bridges`

## Problem

The engine currently accepts `arazzo: "1.0.0"` documents. The parser has no hard version
guard — it accepts any string — but downstream layers do not model the 1.1.0 additions:

- **AsyncAPI source descriptions** — `sourceDescriptions[*].type: "asyncapi"`, plus per-step
  `action: send | receive`, `channelPath`, `correlationId`. `SourceType::Asyncapi` and
  `Step::$action`/`$channelPath`/`$correlationId` already exist (partial 1.1) but are
  neither version-gated nor validated for consistency.
- **Selector Object** — structured `{context, selector, type}` shape that replaces bare
  string templating for outputs / parameters. The `type` pins the expression grammar
  (`jsonpath`+`rfc9535`, `xpath`+`xpath-10..31`, `jsonpointer`+`rfc6901`).
- **Sub-workflow composition** on Success/Failure Action Objects — `workflowId` +
  `parameters` map, chained without leaving the current run. Distinct from the existing
  `goto` action (which is a jump, not a composition).
- **`in: querystring`** parameter location — whole querystring binding, distinct from
  per-key `query`.
- **Root-level `$self`** URI — self-reference for cross-document links.

Fixture `tests/fixtures/parser/arazzo-1.1-cross-protocol-saga.yaml` exists but is stale
(declares `arazzo: 1.0.0` and exercises only Step-level partial-1.1 fields). It will be
rewritten as part of this stub.

## Approach

**Delivery structure**: vertical slice. One branch, one PR, one commit per subsystem
inside it. Substrate is one conceptual thing (the 1.1.0 upgrade) — splitting means 3-4
weeks of half-usable code in main.

**Compatibility posture**: additive. Every 1.1.0 feature = new enum case, new DTO, new
action kind, new resolver evaluator, new executor path. Zero removals from 1.0.0 shapes.
The one breakage: previously silently-accepted stray `arazzo: 1.2.0`-ish strings now
rejected at parse (strict allowlist with patch tolerance).

**Version threading**: `SpecVersion` enum flows from parser → `ArazzoDocument::$specVersion`
→ validator (rule gating) → executor (branch on Async 1.1 semantics). Single source of
truth, no scattered string comparisons.

## Architecture

Layer additions:

- **DTO**: `Selector`, `ExpressionType` enum, `SpecVersion` enum, `SubWorkflowSuccessAction`,
  `SubWorkflowFailureAction`, `ArazzoDocument::$self`, `ArazzoDocument::$specVersion`,
  `ActionKind::Invoke`, `ParameterIn::Querystring`.
- **Parser**: strict+patch version guard, `Selector` branch in output/parameter/replacement
  parsing (YAML shape switch), `invoke` case in action parsers, `$self` root read.
- **Validator**: 4 new rules; 5 existing expression-ref rules widened to `Expression|Selector`.
- **Resolver**: `SelectorEvaluator` router by `ExpressionType`; `XpathEvaluator` interface +
  `DomXpathEvaluator` (XPath 1.0 built-in).
- **Executor**: `SubWorkflowInvoker` — forks child `WorkflowContext`, binds parameters,
  awaits, merges outputs. `AsyncApiStepExecutor` gets `SpecVersion`-aware branch.

## DTOs and Enums

```php
// New enum: derived from parsed `arazzo` string
enum SpecVersion: string {
    case V1_0 = '1.0.0';
    case V1_1 = '1.1.0';
    public static function fromRaw(string $raw): self;  // strict + patch tolerance
}

enum ExpressionType: string {
    case JsonPath    = 'jsonpath';
    case XPath       = 'xpath';
    case JsonPointer = 'jsonpointer';
}

// ParameterIn gains:
case Querystring = 'querystring';

// ActionKind gains:
case Invoke = 'invoke';

// New value object
final readonly class Selector {
    public function __construct(
        public ?string $context,          // e.g. "$response.body"
        public string $selector,          // e.g. "$.data.id"
        public ExpressionType $type,
        public ?string $version = null,   // rfc9535 | xpath-10..31 | rfc6901
    ) {}
}

// New action DTOs (mirror on failure side)
final readonly class SubWorkflowSuccessAction extends SuccessAction {
    /** @param array<string, Expression|Selector|scalar> $parameters */
    public function __construct(
        string $name,
        public string $workflowId,
        public array $parameters,
        array $criteria,
    ) { parent::__construct($name, ActionKind::Invoke, $criteria); }
}

// ArazzoDocument gains:
public ?string $self = null,
public SpecVersion $specVersion,
```

Field type changes (union bump):

- `Step::$outputs`: `array<string, Expression>` → `array<string, Expression|Selector>`
- `Workflow::$outputs`: same bump
- `Parameter::$value`: `mixed` unchanged; parser now emits `Selector` when YAML shape is
  an object with `selector` key
- `PayloadReplacement::$value`: same widening

Consumers (resolver, executor) switch on `instanceof Selector` vs `Expression`.

## Parser Changes

`src/Parser/Parser.php`:

1. After `requireString('arazzo')`, wrap in `SpecVersion::fromRaw()` — throws
   `ParserException::unsupportedVersion` if not `1.0.x` / `1.1.x`. Pass into
   `ArazzoDocument`.
2. New root read: `$self = optionalString($d, '$self', $ctx)`. URI syntax check deferred
   to validator.
3. `parseOutputsMap()`: value can be `string` OR `array` (Selector shape):
   - `string` → `new Expression($v)` (unchanged)
   - `array` with `selector` + `type` → `new Selector(context, selector, ExpressionType::from(type.type), type.version)`
   - other → `ParserException::wrongType(..., 'string|selector-object', ...)`
4. `parseParameter()`: `ParameterIn::tryFrom` message updated to include `querystring`.
   `value` field routed through `parseValueOrSelector()`.
5. `parseSuccessAction()` / `parseFailureAction()`: recognize `type: invoke` →
   `SubWorkflowSuccessAction` / `SubWorkflowFailureAction`. Requires `workflowId`;
   optional `parameters` map.
6. `parsePayloadReplacement()` value routed through `parseValueOrSelector()`.

New helper: `parseValueOrSelector(mixed $node): Expression|Selector|scalar|array`.

## Validator Changes

Existing rules extended:

- `DocumentArazzoVersionRule` → hard-enforce `1.0.x` / `1.1.x` (currently stub-ish; audit
  during plan phase).
- `StepParameterInValidRule` → include `Querystring` case.
- Expression-reference rules (`ExpressionUnresolvedStepRefRule`,
  `ExpressionUnresolvedWorkflowRefRule`, `ExpressionUnresolvedComponentRefRule`,
  `ExpressionUnresolvedInputRefRule`, `ExpressionUnresolvedSourceRefRule`) → gain
  `|Selector` branch that walks `Selector::$selector` through the same resolver.

New rules (4):

- `SelectorTypeSupportedRule` — `Selector::$type` must be in {jsonpath, xpath, jsonpointer}.
  Version pinned to known list per type (`rfc9535` for jsonpath, `xpath-10..31` for xpath,
  `rfc6901` for jsonpointer). Unsupported version → error at validate unless the bound
  `XpathEvaluator` advertises the version (runtime probe via
  `XpathEvaluator::supportedVersions()`).
- `SubWorkflowInvokeTargetResolvesRule` — `SubWorkflow*Action::$workflowId` must resolve in
  current doc OR reachable via loaded `sourceDescriptions` of type `arazzo`.
- `ParameterQuerystringOperationShapeRule` — `in: querystring` only on step whose target
  operation is GET-shape (`GET`, `HEAD`, `OPTIONS`). Cross-references OpenAPI source
  descriptor.
- `SelfUriSyntaxRule` — `ArazzoDocument::$self` must be valid URI
  (`filter_var(FILTER_VALIDATE_URL)` plus `#` fragment allowed).

Plus, belt-and-suspenders for the 1.0 side:

- `AsyncApiFieldsRequire11Rule` — presence of `Step::$action`/`$channelPath`/`$correlationId`
  on a `SpecVersion::V1_0` document = error.

**Version-gated**: `SelectorTypeSupportedRule`, `SubWorkflowInvokeTargetResolvesRule`,
`SelfUriSyntaxRule`, `ParameterQuerystringOperationShapeRule` skip when
`SpecVersion::V1_0`. `AsyncApiFieldsRequire11Rule` runs only on 1.0.

Total rule count: 40 → 45.

## Expression Resolver

New `SelectorEvaluator` (`src/Resolution/SelectorEvaluator.php`):

```php
final class SelectorEvaluator {
    public function __construct(
        private JsonPathEvaluator $jsonPath,
        private JsonPointer $jsonPointer,
        private XpathEvaluator $xpath,
        private ArazzoExpressionResolver $ctx,
    ) {}

    public function evaluate(Selector $sel, WorkflowContext $wf): mixed {
        $rootValue = $sel->context !== null
            ? $this->ctx->resolve(new Expression($sel->context), $wf)
            : $wf->rootScope();

        return match ($sel->type) {
            ExpressionType::JsonPath    => $this->jsonPath->query($rootValue, $sel->selector),
            ExpressionType::JsonPointer => $this->jsonPointer->get($rootValue, $sel->selector),
            ExpressionType::XPath       => $this->xpath->query($rootValue, $sel->selector, $sel->version ?? 'xpath-10'),
        };
    }
}
```

**`XpathEvaluator` interface** (`src/Resolution/Xpath/XpathEvaluator.php`):

```php
interface XpathEvaluator {
    /** @return list<string> supported versions e.g. ['xpath-10'] */
    public function supportedVersions(): array;
    public function query(mixed $rootValue, string $selector, string $version): mixed;
}
```

**`DomXpathEvaluator`** (default, `src/Resolution/Xpath/DomXpathEvaluator.php`):
- `supportedVersions()` → `['xpath-10']`.
- Input must be XML string OR `DOMNode`. PHP array/scalar → `SelectorEvaluationException::xpathRequiresXml`.
- Wraps `loadXML` in `libxml_use_internal_errors(true)` to prevent warning leakage.

**Call-site wiring**:
- `StepOutcomeHandler` (currently reads `$step->outputs` as `Expression`): switch on
  `Expression|Selector`, delegate accordingly.
- `HttpStepExecutor` / `AsyncApiStepExecutor` param resolution: same union switch.

**Composer**:
- `require`: `ext-dom` pinned.
- `suggest`: `"ext-xml": "For XPath-based Selectors in Arazzo 1.1.0 workflows"`.

**Service binding** (`LaravelArazzoServiceProvider`):
- `bind(XpathEvaluator::class, DomXpathEvaluator::class)` — consumers override with
  saxon adapter for XPath 2.0/3.x.

**Error path**: unsupported version at eval time → `SelectorEvaluationException::unsupportedXpathVersion($requested, $evaluator->supportedVersions())`.

## Executor: SubWorkflow Invoke

`src/Execution/SubWorkflowInvoker.php`:

```php
final class SubWorkflowInvoker {
    public function __construct(
        private DefinitionRegistry $registry,
        private WorkflowExecutor $executor,
        private ArazzoExpressionResolver $resolver,
        private SelectorEvaluator $selectors,
    ) {}

    public function invoke(
        SubWorkflowSuccessAction|SubWorkflowFailureAction $action,
        WorkflowContext $parent,
    ): SubWorkflowResult {
        $target = $this->registry->getWorkflow($action->workflowId)
            ?? throw ExecutionException::subWorkflowNotFound($action->workflowId);

        $bound = [];
        foreach ($action->parameters as $name => $valueSpec) {
            $bound[$name] = match (true) {
                $valueSpec instanceof Expression => $this->resolver->resolve($valueSpec, $parent),
                $valueSpec instanceof Selector   => $this->selectors->evaluate($valueSpec, $parent),
                default                          => $valueSpec,
            };
        }

        $child = WorkflowContext::forChildInvocation(
            parent: $parent,
            workflow: $target,
            inputs: $bound,
        );

        $outcome = $this->executor->execute($target, $child);

        return new SubWorkflowResult(
            outputs: $outcome->outputs,
            terminal: $outcome->terminal,
            childRunId: $child->runId,
        );
    }
}
```

**`WorkflowContext::forChildInvocation`**: new named ctor. Child gets:
- Fresh `variables` scope seeded with `$bound` under `$inputs.*`.
- Own `runId` (uuid), links back via `parentRunId` for observability.
- Same source registry, event dispatcher, dependency graph.
- No access to parent `$steps.*` — child is isolated (spec-compliant).

**`SubWorkflowResult`**: read-only DTO. `outputs` become accessible in parent as
`$actions.<actionName>.outputs.*` inside the successor step's expression scope.

**`StepOutcomeHandler` wiring**: when handling `onSuccess` / `onFailure`, detect
`SubWorkflow*Action` → route to `SubWorkflowInvoker`, then continue parent workflow with
result exposed. Existing goto path untouched.

**Event catalog**: emit `SubWorkflowInvoked`, `SubWorkflowCompleted`, `SubWorkflowFailed`
(pending `core-38-event-dispatcher-wiring`). Until that ships, dispatch through the
existing `ExecutionEvent` bus.

## Executor: AsyncAPI 1.1 Branch

`AsyncApiStepExecutor` today reads `$step->channelPath`, `$step->correlationId`,
`$step->action` if present. No validation of consistency, no 1.0 vs 1.1 gate.

Changes:
- `SpecVersion::V1_0`: presence of any of `channelPath`/`correlationId`/`action` = parser-
  layer parse error (via `AsyncApiFieldsRequire11Rule`).
- `SpecVersion::V1_1`: `action` required-when-source-is-asyncapi (`send` | `receive`).
  `channelPath` required. `correlationId` required for `receive`.
- Resolver invocation of `correlationId` unchanged (`Expression`) — 1.1 does not upgrade
  this field to Selector shape.

**Migration risk**: any existing consumer using partial-1.1 fields on a `1.0.0` doc will
now fail parse. No such consumer known; sole fixture is the one this stub owns and will
rewrite.

## Migration + CHANGELOG

CHANGELOG under `## Unreleased`:

`### Added`
- Full Arazzo 1.1.0 spec support (parser, validator, resolver, executor).
- `SpecVersion` enum, `Selector` DTO, `ExpressionType` enum,
  `SubWorkflowSuccessAction`/`FailureAction`, `ArazzoDocument::$self`.
- `XpathEvaluator` interface + `DomXpathEvaluator` (XPath 1.0 built-in, `ext-dom`).
- `ParameterIn::Querystring`, `ActionKind::Invoke`.
- 5 new validator rules (`SelectorTypeSupportedRule`, `SubWorkflowInvokeTargetResolvesRule`,
  `ParameterQuerystringOperationShapeRule`, `SelfUriSyntaxRule`, `AsyncApiFieldsRequire11Rule`).

`### Changed` (breaking)
- `arazzo` field now guarded: only `1.0.x` and `1.1.x` accepted. Prior versions rejected at parse.
- AsyncAPI-specific step fields (`action`, `channelPath`, `correlationId`) now rejected on
  `1.0.0` documents. Move such docs to `arazzo: 1.1.0`.

## Acceptance

1. Comprehensive fixture (`arazzo-1.1-cross-protocol-saga.yaml`) parses + validates +
   executes end-to-end green against mock HTTP server and mock AsyncAPI broker.
2. 1.0.0 fixtures unchanged, green.
3. New public API additions SemVer-minor safe (only additions, no removed signatures).
4. PHPStan max level clean (`phpstan.neon.dist`).
5. Pest coverage ≥ existing baseline (no drop).

## Out of Scope

- Reverse translation (`1.1.0` → `1.0.0`) — no consumer for it.
- Migrating existing 1.0 fixtures to 1.1 shapes — 1.0 stays supported.
- XPath 2.0/3.x built-in implementation — interface only; consumers plug saxon.
